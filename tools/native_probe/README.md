# ACU native probe

This is a Windows x64 in-process observation framework and a separate executable
launcher. The original ACU executable is never patched, renamed or replaced.
No game function addresses or structure layouts are enabled automatically.
Generic facilities apply to animation, skeletons, movement, climbing/traversal,
collision/raycast, physics, input, camera, AI, world/streaming and rendering;
their meanings still require independent target and layout recovery.

## Build and run

From the project directory, with existing MSVC 2022 x64 BuildTools:

```powershell
./tools/native_probe/build.ps1
./local/native-probe/ACU-Probe.exe
```

The convenient zero-argument executable reads adjacent ignored `launch.ini`
(`[launch] exe=...`) generated from `python tools/acu.py paths` and loads adjacent
`acu_probe.dll`. All outputs stay under ignored `local/native-probe/`.
Advanced modes:

```powershell
./local/native-probe/acu_probe_launcher.exe --launch "<game-directory>/ACU.exe" --dll "$PWD/local/native-probe/acu_probe.dll"
./local/native-probe/acu_probe_launcher.exe --attach 1234 --dll "$PWD/local/native-probe/acu_probe.dll"
python tools/native_probe/client.py 1234 command STATUS
./tools/native_probe/command.ps1 -ProcessId 1234 -Command MODULES
```

The launcher accepts only original executable SHA-256
`748abdc6456397fe7d8080f975f2a5ed3123bce548e7bf1c68b23f47e8b27e40`
or the exact synthetic fixture hash generated by its own build. The original
must initialize its primary-thread loader normally before DLL injection. The
fixture validates the fully suspended-primary injection path. A failed fixture
injection terminates only that newly spawned suspended fixture; a game that
already started remains running on injection failure. Attach never terminates
its target. Remote system export addresses use enumerated remote module bases;
initial fixture loader bootstrap verifies ntdll header/code bytes before use.

`injected:true` reports successful LoadLibrary completion, not a healthy game
session. The launcher separately observes original-game startup for3seconds,
checks a bounded STATUS round trip, and emits `process_running`,
`process_exit_code`, `probe_status_ready` and `startup_observation_ms`. Exit6
means injection failure,7 means the process exited,8 means STATUS unavailable.
This observation covers that interval only, not subsequent gameplay stability.
On this machine direct original launch, without instrumentation, was
observed to exit code42 after approximately3seconds. Startup injection succeeded
once but that process also exited before a sustained STATUS round trip. These
are platform/game startup availability limits; original-game telemetry remains
unvalidated until a normal game session is available. Read-only installed-game
registry evidence identifies Ubisoft Launcher install720. A user/platform
launched game can be attached by explicit PID. Do not claim fixture results as
original-game parity.

## Transport and limits

The pipe `\\.\pipe\acu-probe-<PID>` rejects remote clients and uses the default
Windows process security descriptor. One local client/command at a time. Send
one ASCII command in one write (max65535bytes); receive one JSON line; send
`ACK` before closing. The bundled clients implement this acknowledgement so a
disconnect cannot discard unread response bytes. Pipe transfers timeout after
30seconds. Access is intended for the local collaborating user, not a network
service or privilege boundary.

| Command | Effect and bound |
| --- | --- |
| `STATUS` | PID, ASLR image base, QPC frequency, hooks/hits/drops/conflicts, capabilities |
| `MODULES` | Names, local paths, ASLR bases and sizes |
| `THREADS` | Current process thread IDs |
| `REGIONS [hex-VA]` | Up to256 VirtualQuery regions, protections/state/type and pagination address |
| `READ hex-VA decimal-length` | Exact bounded read,1..65536bytes; inaccessible/partial reads fail |
| `HOOK slot hex-RVA expected-lowercase-hex label [every register-index signed-offset bytes]` | Verified executable-site probe, slots0..3, expected bytes1..32; sample size0..256 |
| `HOOKVA slot hex-VA expected-lowercase-hex label [every register-index signed-offset bytes category]` | Same guards for an absolute executable address in any loaded module |
| `UNHOOK slot` | Restore affected debug-register slot to its original state |
| `EVENTS [count]` | Drain bounded ring; return newest up to256events, discard omitted older events |
| `WATCH label hex-VA decimal-length` | Up to32 absolute-memory watches, each1..4096bytes |
| `WATCHES` | Latest bytes and cumulative samples/changes/read failures |
| `UNWATCH label` | Remove watch |
| `SHUTDOWN` | Restore debug registers, stop worker and pipe; leave inert DLL/VEH resident |

`HOOK` RVAs are relative to the **main executable**. An RVA, executable-page
protection and a byte match are necessary guards, not proof of function identity.
Call sites must first be mapped to the installed/live image; corpus export VAs
cannot be copied as verified offsets. Expected-byte matching requires exact
lowercase hexadecimal without `0x` or whitespace. Labels have no whitespace.
An optional final category token follows the four sampling arguments. Every
event preserves its own immutable label/category/revision/address across slot
rotations. The handler requires both a registered address and its owned DR6 slot
bit; unrelated single-step exceptions continue through the exception chain.
Function prologues are optional: a separately verified post-call instruction
site can capture RAX/XMM0 and output buffers as another labelled probe. That
requires recovered ABI/native semantics. There is no speculative automatic
return breakpoint or unwind engine.

Register array order is RCX,RDX,R8,R9,RAX,RBX,RSI,RDI,RBP,RSP,R10,R11,R12,R13,R14,R15.
Each event records QPC time, sequence, thread, slot, RIP, all16GP registers,
XMM0..5 raw96bytes, up to64bytes at RSP (caller/arguments), and optional memory
at selected register+signed offset. Snapshot reads occur inside the handler;
pointer failures yield empty/partial data, never fabricated structures. They add
latency and may alter game scheduling. Pointer snapshots and module snapshots
are not coherent cross-thread captures. Stack bytes are not an unwound callstack.

Hardware execution breakpoints preserve original instructions and ABI, but
only **four sites concurrently per thread** are available. Threads with
pre-existing occupied slots are skipped for those slots and counted as
conflicts. A debugger attached at HOOK time rejects activation. Do not attach a
debugger or another hardware-probe owner while these probes are active. Existing
threads are briefly suspended to set/restore debug registers. Their original
registers are saved, thread creation stamps distinguish recycled IDs, and new
threads are refreshed at roughly50ms; short-lived threads can escape coverage.
Known threads are not repeatedly suspended while hook revision is unchanged.
The probe worker is excluded. Exception handlers are not an invisible observer:
measure overhead before using a high-frequency site.

The256event ring drops on contention and overwrites oldest records when full;
STATUS reports combined drops/overwrites. Event sequence counts all captured
hits before sampling. `every=N` samples each Nth hit independently per slot.
Watch polling is approximately20Hz while idle and can pause while a client is
connected; `WATCHES` samples explicitly. Watches are **not frame-synchronized
bone capture**. Entry/post-call correlation is by thread/site/time and can be
incomplete because of nested calls, lost events, rotation, or thread coverage.
Owned breakpoint sites are retained in a bounded tombstone table so pending
single-step exceptions remain handled after UNHOOK. SHUTDOWN deliberately leaves
the inert DLL and this handler resident until process exit; unloading executable
handler code during a pending exception would risk a use-after-unload.

## Whole-image recovery and sessions

For controller-first menu entry, bounded XInput sweeps and the category checkbox
launcher, see
[`docs/CONTROLLER_AUTOPLAY.md`](../../docs/CONTROLLER_AUTOPLAY.md). The runner
can capture read-only memory checkpoints and correlate a concurrent verified
native probe session with decompile-name candidates.

An opt-in native startup dump can capture a short-lived original before orderly
exit without pipe round-trip overhead. Set `$env:ACU_PROBE_STARTUP_DUMP='1'`
and optionally `$env:ACU_PROBE_STARTUP_DUMP_DELAY_MS='500'` (0..2000), then run
the launcher. The worker writes unique `startup-PID-TICK.mapped.bin` and `.json`
adjacent to the DLL, capped at512MiB main image; manifest records module base,
regions/protections/read holes, disk/mapped SHA256, QPC times and completeness.
It does not enable any hooks or decode structures. This sequential sample may
still contain packed or partially unpacked code; inspect contents before using
it as native evidence. Remove these environment variables after capture.

```powershell
python tools/native_probe/client.py 1234 dump local/native-probe/live-session
python tools/native_image.py local/native-probe/live-session/main-image.mapped.bin local/native-probe/live-inventory --mapped --live-base 0xBASE
python tools/decompile_xref.py local/native-probe/live-inventory/functions.jsonl local/native-probe/live-inventory/summary.json "ACU - Decompiled" local/native-probe/live-xref
python tools/decompile_xref.py local/native-probe/live-inventory/functions.jsonl local/native-probe/live-inventory/summary.json "ACU - Decompiled" local/native-probe/live-xref --session local/native-probe/session.jsonl
python tools/native_probe/client.py 1234 scan 0000000012340000 65536 "48 8b ?? 24"
python tools/native_probe/client.py 1234 dump local/native-probe/all-memory --all-regions --max-bytes 4294967296
python tools/native_probe/client.py 1234 session local/my-verified-profile.json local/native-probe/session.jsonl --seconds 60 --max-bytes 16777216
```

Main-image output preserves mapped RVA layout, zero-filled holes and a manifest
of region protection/state, every unreadable range, module identity, source
disk executable SHA-256 and captured live-file SHA-256. Reads are64KiB with4KiB
fallback; guard/inaccessible/noncommitted pages are skipped. It is a sequential
capture while the game runs, not an atomic snapshot. `--all-regions` creates
separate files with absolute region bases and explicit4GiB default budget;
larger committed-memory scopes must be requested explicitly. Dumps contain game
bytes and possibly sensitive process data: keep them in ignored machine-local
storage. Scan is bounded64MiB/256-byte pattern/256matches and reports holes.

`profiles.example.json` provides subsystem categories but intentionally has no
unverified offsets. Add `probes` objects with `label`, hex `rva`, `expected_hex`,
optional `every`, `register_index`, `offset`, `bytes`, `category` and `module`.
`module` selects one loaded module name, bounds its RVA, and uses HOOKVA;
the session header records module paths/bases/disk hashes. Session profiles rotate
groups of up to4 probes, emit group metadata/time/status and bounded JSONL,
and remove active probes on exit. Categories are organizational metadata,
not implemented semantic decoders. Rotated groups observe different time
windows: whole-profile breadth does not mean whole-engine simultaneous coverage.
An optional `redirect` object can set `slot`, `from_index`, `to_index`,
`return_module` and hex `return_rva`; the exact conditional RCX redirect is
applied before the session emits `armed`. It requires a redirect-capable probe
DLL. The controller replay waits for that flushed `armed` record before sending
input. A regular probe DLL rejects the command, and no replay should start on
that failed session.
When `controller_autoplay.py` receives `--expected-user-index`, it skips the
moving stick calibration pulse and verifies the first non-neutral XInput
readback against the requested report. Without that option it discovers the
slot with the pulse and confirms release before replay.
Use separately labelled entry and verified post-call sites for traversal tests
and raycast arguments/results when those native layouts are recovered.

## Verification and restoration

### Read-only exact signature discovery

Hit-capped scans now record `partial_chunk` and `resume_address`; `next_address`
uses that resume point. A single pattern resumes at the last hit plus one byte.
Multiple patterns resume at the chunk start and may duplicate prior hits;
deduplicate and choose an adequate hit budget. Cross-chunk overlap at a resume
boundary still needs broader controls.

### Runtime image analysis view

When disk code is absent but live bytes exist, preserve a separate analysis view:

```powershell
python -m tools.native_probe.runtime_analysis_view <pid> local/runtime-view --expected-sha256 <exe-sha256>
python -m unittest tools.test_runtime_analysis_view
```

Requires the existing probe transport and clear hooks. Verifies disk hash,
preserves the mapped source dump and emits a separate PE with section raw ranges
mapped to RVAs, live ImageBase, cleared checksum/certificate directory. Reports
hashes, read failures and header changes; refuses an existing output directory.
This is a non-atomic static-analysis input, not a runnable reconstructed binary.
Runtime imports/patches and any unreadable-page holes remain; inspect its manifest.
See [ACU-RE-0025](../../docs/findings/ACU-RE-0025-player-root-full-rig.md).

### Signature scanner usage

`scan_memory_signature.py` uses external `VirtualQueryEx` and
`ReadProcessMemory`; it does not need an injected probe. It verifies the PID's
executable path and required SHA-256 before scanning. Supply reference bytes
through one or more `--pattern-file` arguments and explicit address bounds:

```powershell
python tools/native_probe/scan_memory_signature.py <pid> local/signature-scan.json --pattern-file local/reference.bin --expected-sha256 <exe-sha256> --start 0x100000000 --end 0x180000000
```

The output records exact hits, reference hashes, readable-byte coverage, failed
reads, and the stopping address/reason. Defaults bound successful reads to
4 GiB, elapsed time to 45 seconds, and hits to 256; `--max-bytes`,
`--max-seconds`, and `--max-hits` are explicit overrides. Existing outputs are
refused. Patterns are limited to 4,096 bytes each and 256 files. Reads skip guard
and inaccessible regions and preserve protection settings. Pattern overlap is
retained between chunks within a region; patterns spanning separate regions or
failed reads may be missed. Buffers race application writers. A byte match or
pointer match alone does not identify a player or establish object ownership.
See [ACU-RE-0024](../../docs/findings/ACU-RE-0024-pose-signature-rediscovery.md)
for the positive/negative controls and current ACU pose discovery evidence.

```powershell
python tools/native_probe/test_fixture.py

```

The independent fixture exports an actual noinline tick function and counter.
Regression checks actual RCX=1 argument, RIP/export correspondence, register and
stack telemetry, watch changes/counter progression, byte mismatch/unreadable
refusals,100 hook/unhook cycles (including pending-exception races), mapped MZ
capture, and survival after SHUTDOWN. The fixture is synthetic and does not
validate animation, traversal, collision or raycast semantics.

No original install files have been deployed/replaced by this framework. Restore
runtime state with SHUTDOWN, then exit/restart the game to remove the inert DLL.
Delete ignored build/output files only when no process has the DLL loaded. The
optional controller runner uses the archived official ViGEmClient SDK built in
ignored `local/native-probe/ViGEmClient-src/`; see the controller guide for the
upstream commit and license. No third-party detour implementation is used.
